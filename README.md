# Oracle2ClickHouse-Batch

Lightweight data pipeline that extracts from Oracle, stages Parquet files to MinIO, and loads into ClickHouse. Orchestrated with Apache Airflow. This README provides the minimal, accurate usage and configuration instructions developers need to run and extend the project locally.

## What's in this repo

- `src/dags/` — Airflow DAG generator and DAG definitions.
- `src/dags/include/utils/` — helpers: `clickhouse.py`, `minio.py`, `oracle.py`, `audit.py`.
- `src/dags/include/table_specs/` — YAML table specs used by the DAG factory.
- `docker/` — Docker images for local dev services (Airflow, MinIO, ClickHouse, Oracle stub).
- `manage.sh` — convenience script to start/stop the local stack.

## Quick start (local development)

1. Copy environment file and configure credentials (Airflow Connections preferred):

```bash
cp .env.example .env
```

2. Start the local services (this will use Docker Compose):

```bash
./manage.sh up
```

3. Open Airflow UI at http://localhost:8080 and verify DAGs appear. DAGs are generated by `dag_factory.py` from the YAML specs folder.

4. Trigger a DAG run from the UI to run an extraction -> staging -> load flow.

Notes:
- Services expected by the project: Oracle (1521), MinIO (9000), ClickHouse (8123/9000), Airflow (8080). The `docker/` directory contains images and configs for local dev.

## Configuration (table specs)

Place each table spec YAML under `src/dags/include/table_specs/<domain>/<table>.yaml`. Minimal fields:

```yaml
table_id: "schema.table"
sync_mode: "full" # or "incremental"
schedule: "@daily"
incremental_key: "last_update_ts" # required for incremental
drop_columns: []
clickhouse:
    database: "analytics"
    table: "table_name"
    engine: "MergeTree"
    order_by: ["col1", "col2"]
    partition_by: "toYYYYMM(col_date)"
```

The DAG factory reads these files and creates one DAG per `table_id`.
